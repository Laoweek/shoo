# Subscribed channels read from youtube.com/feed/channels in the background

A remove Rule can skip Subscribed channels (REQ-RULE-14), so Shoo needs the user's subscriptions. YouTube shows them on one page, `/feed/channels`, about 11 MB of HTML for 1,000 channels, with every channel's id, handle and name in `ytInitialData`. Shoo reads that page from the background with the user's YouTube cookies, through the youtube.com host permission it already has, at most about once a day and only while a Rule uses the option. It keeps only the channel keys. The content script would have the session for sure, but it would hold the page in a YouTube tab, carry the parser in the size-limited content bundle, and have to hand the list to the background through a new message.

A Tile from a Subscribed channel is asked only the Rules that apply to it, in requests of its own, and its answers are cached under their own key (`cacheVersion`). Asking every Rule and ignoring a skipping one afterwards would be cheaper to build, but a choice question names one Rule, so a Tile that matched a skipping Rule best would hide a match with another Rule.

**Consequences**: one 11 MB download a day while the option is on. Without a usable list, a Tile a skipping Rule would remove is held undecided rather than removed, so a failed read (signed out, the page changed, a browser that does not send the session with a background request) makes those Rules remove only Tiles that show no channel. Accounts whose page has continuation items count channels past the first page as not subscribed. Reading the list through YouTube's internal API, or from the content script, is the way out if the page goes away. A Tile from a Subscribed channel goes in text requests of its own with only the Topic rules that apply, and its thumbnail request has only the Thumbnail rules that apply, so the shape of the requests shows the Decision provider which Tiles come from Subscribed channels, though never the list itself (2026-11-04, `decision-engine.md` Section 10). Putting those Tiles in shared requests needs a calibration run first and a new ADR. The list is deleted as soon as no Rule skips Subscribed channels.
